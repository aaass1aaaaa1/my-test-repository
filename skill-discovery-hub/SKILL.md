# 技能发现与安装中枢

技能市场里的「找 → 挑 → 装 → 评」单一入口：输入一句需求，输出候选清单与推荐理由，经用户确认后完成安装。

## 30 秒速查卡

```
说需求 → 扩关键词 → 搜（合并去重）→ 表格呈现 → 用户挑 → 确认后装 → 如实汇报
```

## 工作流

### Step 1 解析意图

从用户输入抽取两个槽位：

- **keyword（检索词）**：用户关心的功能或对象，如「PDF」「数据分析」「会议纪要」。用户只说「找个 skill」而无具体词时留空，走纯分类浏览。
- **tag（一级分类，可选）**：用户点名的大类，如「办公效率」「数据分析」。只把用户原话作为分类候选，不臆造分类名；市场实际类目以平台返回为准。注意：`references/category-map.md` 的 11 大分类是生态选型地图，与市场类目是两套体系，勿混用。
- **置信度不足时**：输入仅剩泛指词（「这个」「帮我弄一下」）→ 按 `references/confidence-gating.md` 提问补齐，不猜；推荐依据不确定 → 结论标 `[需核实]`，不用「大概」糊弄。

同时判定模式，路由如下：

| 用户表达 | 模式 | 动作 |
|---|---|---|
| 「找个 X 技能」「搜一下 X」 | A 纯关键词 | Step 1–4 后呈现，不安装 |
| 「按分类看技能」「有哪些分类」 | B 分类浏览 | 用分类名作检索词拉取，按分类聚合呈现 |
| 「办公效率类里处理 PDF 的」 | C 组合检索 | 关键词召回 ∩ 分类过滤 |
| 「推荐一个做 X 的」「该装哪个」 | D 推荐选型 | Step 1–5，给推荐理由 |
| 「如何做 X」「有能做…的吗」 | E 需求询问 | 把 X 解析为检索词走 A；命中则推荐并询问是否安装，未命中则说明并给替代建议 |
| 「装这个」「安装第 N 个」 | 安装 | 直接进 Step 6 |
| 「这个技能靠谱吗」 | 评估 | 按六维标准回答（见 references/quality-standards.md） |

### Step 2 扩展关键词

- 中英文各备一版（如「PDF」↔「文档处理」「文档解析」），补近义词与场景词。
- 整句优先，最多取 4–5 个查询词；不堆砌无关词。
- **默认路径**：将全部查询词作为**一个关键词数组**单次传入（本环境检索工具接受 1–5 个关键词短语）。
- **降级路径**：仅当工具只接受单个检索词时，才改为逐词多次调用（规则见 Step 3）。

### Step 3 检索并合并

- 通过 ToolSearch 加载 `search_and_install_skills`，以 `action: "search"` 调用，Step 2 的关键词数组**一次传入**。
- **禁止并发**：同一时刻只允许一个检索或安装调用在执行，并行第二个会直接报错，必须排队。
- 仅当走了降级路径（逐词多次调用）时：合并各次返回，按 `name` 去重，保留首次出现记录；某次报错 → 透传错误并停止；某词零命中 → 继续其余词，全部落空才告知未找到。
- **检索范围注意**：该工具只返回**尚未安装**的技能，已安装状态不在其结果里；查是否装过用 `skill_management`（见 Step 5）。
- 若环境提供 `workbuddy_marketplace_skill`（keyword/limit/skillId 接口）：逻辑相同，`limit` 取 10–20。

### Step 4 排序与呈现

- 相关度排序：名称命中 > 描述命中 > 分类命中。
- 呈现表格，基础字段：`display_name`、一句话描述（截断至约 60 字）、推荐理由。
- 「是否已安装」列**只在 Step 5 查重后有数据才显示**；检索结果本身只含未安装技能，查不到就**不显示该列**，不留空、不编造。
- 不向用户暴露内部 `name` / `skillId`。
- 零命中 → 如实告知「未找到直接匹配的技能」，给 2–3 个近义检索建议，并提示可考虑自建（规范见 references/quality-standards.md）。

### Step 5 选型把关（多候选时执行）

- **先查重**：需求可能已被现有技能覆盖。用 `skill_management`（action: "list"）核对已安装技能，够用就建议先用现有的，不重复安装；查重结果同时作为 Step 4 表格「是否已安装」列的唯一数据来源。
- **重叠裁决**：候选间功能重叠时，按六维质量标准打分（见 references/quality-standards.md），给出主力建议；不诱导用户全装。
- **危险信号明示**：演示性质、隐式依赖、绑定单一平台、描述只有形容词——看到就当面指出。

### Step 6 安装（需用户明确确认）

1. 仅在用户明确表达安装意图（「装这个」「帮我装上」「安装第 2 个」）或接受推荐后同意安装时执行；不擅自静默安装。
2. 安装前**重新搜索一次**，从最新返回中取目标技能的安装凭证，逐字复制，禁止凭记忆或臆造：
   - 默认路径（`search_and_install_skills`）：凭证是 `name`。
   - 备援路径（`workbuddy_marketplace_skill`）：凭证是 `skillId`；该 id 不得向用户展示，仅用于 install 调用。
3. 提交安装：默认路径用 `action: "install"`，`skill_names` 数组只含本次确认的目标；备援路径用 `action: "install"` 传对应 `skillId`。
4. 逐项如实报告结果：`installed` / `already_installed` / `refused`，失败项不得宣称已安装。
5. 备援路径报错时按 `references/error-codes.md` 的码表处置；遇 `[UNKNOWN_SKILL_ID]` 不重试同一 id，重新 search 取新 id 再装。
6. 安装完成后不自作主张触发该技能的后续动作，交还用户决定何时使用。

### Step 7 汇报

- 结论先行：装了几个、哪些跳过、哪些失败、各自原因。
- 存在同域多技能时，提醒互相抢触发的风险，给合并或停用建议。

## 边界与红线

- **安装必须确认**：没有明确意图就不调用 install。
- **禁止伪造**：不臆造技能名、分类名或不存在的技能；安装用的 `name` 必须逐字来自最近一次搜索返回。
- **不担保质量**：不对第三方技能的功能、安全性做背书，不审查源码；评估只按公开描述与六维标准。
- **不全量枚举**：除非用户明确要「看全部 / 按分类看」，不一次拉取并罗列整个市场。
- **降级透明**：分类字段缺失时的近似匹配、零命中时的降级建议，必须向用户声明，不得伪装成精确结果。
- **缺失就问**：关键信息（装哪个、哪个分类）缺失时问一次，不猜。
- **失败不静默**：任一步失败，输出已完成部分与失败原因。

## 输出规范

- 格式：Markdown；候选用表格，安装汇报用逐项列表。
- 结构：结论先行 → 依据（命中了什么）→ 待确认项。
- 语气：极简、直接、不客套；推荐必须附理由。

## 示例

**示例 1：完整链路（找 → 挑 → 装）**

输入：

```
找个处理 PDF 的技能
```

输出（节选）：

```
关键词数组：["PDF", "文档处理", "pdf 解析"]
命中 3 个候选（单次数组调用）：

| 技能 | 说明 | 推荐理由 |
|---|---|---|
| PDF 工具箱 | 合并/拆分/转换 PDF | 名称+描述双命中 |
| 文档解析器 | 多格式文档结构化抽取 | 场景匹配 |

要装哪个？确认后我再安装。
```

用户回复「装第 1 个」→ 重新搜索取最新 `name` → install → 汇报：「已安装：PDF 工具箱（v1.2.0）」。

**示例 2：选型建议（D 模式）**

输入：

```
自我改进类的技能该装哪个？
```

输出：5 个候选表格 + 重叠分析（如「1 和 2 功能重叠，建议留一个主力」）+ 推荐组合与理由 → 用户确认后进入 Step 6。

**示例 3：需求询问（E 模式）**

输入：

```
有没有能自动生成会议纪要的技能？
```

输出：将「会议纪要」作为检索词执行 Step 1–4；命中 → 推荐最相关技能并询问「是否需要为你安装」；未命中 → 明确告知暂无现成技能，给近义建议或自建路径。
