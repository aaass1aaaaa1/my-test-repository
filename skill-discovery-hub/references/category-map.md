# 分类地图与检索策略

## 按场景找，不按技术名词找

错误方式：「有没有 LangChain 技能？」——这是技术名词，可能根本没人做过，也可能有更合适的方案。

正确方式：「我要让 Agent 能查公司内部知识库并回答」——这是**真实用例**，可以从「数据与分析」「文档处理」「协作与项目管理」多个分类命中候选。

## 11 大分类速查

| 分类 | 什么时候往这找 |
|---|---|
| 文档处理 | 要生成/解析 Word、PDF、PPT、Excel |
| 开发与代码工具 | 写代码、生成 changelog、搭 MCP、测 Web 应用 |
| 数据与分析 | CSV 汇总、深度检索、数据库查询 |
| 商业与营销 | 品牌规范、竞品分析、线索调研 |
| 沟通与写作 | 内容创作、会议纪要、邮件 |
| 创意与媒体 | 设计稿、图片处理、GIF、视频 |
| 生产力与组织 | 文件整理、发票归档、简历 |
| 协作与项目管理 | 工单、文档协作、评审流程 |
| 安全与系统 | 取证、威胁狩猎、系统审计 |
| 辅助技术 | 无障碍、辅助交互 |
| 应用自动化 | 连接外部 SaaS（CRM/工单/邮件/日历/社媒等 17 子类） |

## 应用自动化的 17 个子类

CRM 与销售 / 项目管理 / 沟通 / 邮件 / 代码与 DevOps / 存储与文件 / 表格与数据库 / 日历与排程 / 社交媒体 / 营销与邮件营销 / 客服与工单 / 电商与支付 / 设计与协作 / 分析与数据 / HR 与人事 / 自动化平台 / 会议。

**判断要不要用「应用自动化」类技能**：如果任务的本质是「把 Agent 连到某个外部 SaaS」，先找这一大类，通常已有现成连接器，不用自己写。

## 检索策略

1. **先定位 2-3 个可能命中的分类**（允许跨类）。
2. 在每个分类下按**用例动词**找：生成 / 提取 / 汇总 / 转换 / 监控。
3. 找到候选后，用质量标准筛（见 `quality-standards.md`）。
4. 都找不到 → 考虑自建（遵循贡献规范）。

## 交叉验证

不要只看一个来源。同一个需求，在**官方库、社区索引、技能市场**都搜一遍，取交集里评价最好的。
