# 晋升与提取指南

把账本里的经验提炼到长期位置的两条路径：晋升为项目记忆规则、提取为独立技能。两条路径都遵守「先提案、经确认、再落盘、后标状态」。

## 路径一：晋升到项目记忆

### 触发条件（满足任一）

- 经验跨多个文件/功能适用
- 任何协作者（或未来的自己）都应该知道
- 能防止重复犯错

不满足以上条件的经验留在账本里，不晋升。

### 晋升目标对照

| 目标文件 | 适用内容 |
|----------|----------|
| `AGENTS.md` | Agent 工作流、工具用法、自动化规则 |
| `.cursor/rules/` | Cursor 持久化规则（项目约定、编码标准） |
| `CLAUDE.md` | 项目事实与约定（Claude 系列 Agent） |
| `.github/copilot-instructions.md` | GitHub Copilot 项目上下文 |
| `SOUL.md` | 行为准则、沟通风格（OpenClaw 工作区） |
| `TOOLS.md` | 工具能力、集成陷阱（OpenClaw 工作区） |
| WorkBuddy 环境的 `.workbuddy/memory/MEMORY.md` | 项目级长期规则 |

环境里已有记忆体系时，优先写入环境既有文件，不另起炉灶。

### 晋升三步

1. **蒸馏**：把冗长条目压缩为一条可执行规则（一句话，动词开头，带条件）。
2. **写入**：追加到目标文件的合适章节（不存在则创建，不覆盖已有内容）。
3. **标状态**：原条目状态改 `promoted`，元数据标注 `**已晋升**: <目标文件>`。

示例：账本记录「项目用 pnpm 而非 npm，`npm install` 失败，锁文件是 `pnpm-lock.yaml`」→ 蒸馏为 `包管理器：pnpm（非 npm），使用 pnpm install` → 写入 `AGENTS.md` 构建与依赖章节。

## 路径二：提取为独立技能

### 触发条件（满足任一）

- 重复出现：`参见` 链接指向 2+ 个相似问题
- 已验证：状态为 `resolved` 且有可用修复
- 非显而易见：需实际调试/调查才能发现
- 广泛适用：非项目专属，可跨代码库使用
- 用户指定：用户说「保存为技能」等

### 提取流程

1. **提案**：向用户说明要提取什么技能、解决什么问题、依据哪几条经验；用户确认后才继续。
2. **生成**：按技能创建规范生成 `SKILL.md`（结构、frontmatter、红线以市场规范为准）。
3. **验证**：跑技能校验脚本，FAIL 项修到 PASS。
4. **落盘安装**：产物落盘到使用者技能库目录并安装生效。
5. **标状态**：原条目状态改 `promoted_to_skill`，元数据添加 `Skill-Path: <技能路径>`。
6. **新会话验证**：提示用户在新会话中确认技能可独立触发。

## 重复模式检测

账本膨胀后的系统性修复路径：

1. **先搜索**：在 `.learnings/` 中按关键词搜索已有条目。
2. **关联**：新条目在元数据加 `参见: <已有条目ID>`。
3. **升级**：反复出现的从 `medium` 升至 `high` 或 `critical`。
4. **系统性修复**：
   - 缺文档 → 晋升至项目记忆
   - 缺自动化 → 写入 Agent 工作流
   - 架构问题 → 创建技术债工单

**自动晋升条件**（重复模式同时满足）：出现次数 ≥ 3、出现在至少 2 个不同任务中、30 天内发生。

## 红线

- 晋升/提取是提案，不是既成事实——未经用户确认不得写入长期位置。
- 每次晋升/提取前，先在账本留下一条记录（改了什么、为什么、依据哪几条经验 ID），保证长期记忆的任何变更可追溯。
- 单次、局部、未验证的经验不晋升——晋升门槛是「多次验证 + 跨场景适用」。
