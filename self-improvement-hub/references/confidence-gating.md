# 置信度门控

记录与汇报时的质量门禁：信息不全时不编造，依据不足时不装懂。适用于 Step 2 写条目、Step 4 提晋升/提取提案、Step 5 出每日方案。

## 占位符规则

信息不足时，对应字段写占位符，**严禁脑补**：

| 占位符 | 使用场景 |
|--------|----------|
| `[需核实:正确做法]` | 错误原因已定位，但修复方案未验证 |
| `[需核实:触发条件]` | 模式只出现过一次，不确定复现条件 |
| `[需核实:预期结果]` | 流程未跑完，结果未知 |
| `[需核实:适用范围]` | 不确定经验是否跨场景适用 |

## 置信度三级

| 等级 | 判据 | 处置 |
|------|------|------|
| 高（≥90%） | 依据充分：多次复现、修复已验证、用户已确认 | 直接记录/提案 |
| 中（60–89%） | 有依据但未完全验证 | 记录并在摘要标注「未验证」；提案时说明依据强度 |
| 低（<60%） | 单次发生、仅推测、上下文缺失 | 不写成经验条目；只作为待观察线索记录，或先问用户补齐 |

## 门控判定

```
写条目/提提案前问自己：
  依据是什么？—— 复现次数、验证状态、用户确认
  信息缺什么？—— 缺的字段用 [需核实:字段] 占位
  敢让未来会话直接信吗？—— 不敢就降级为低置信度处置
```

## 红线

- 不用「大概」「可能」「应该是」糊弄字段——要么验证后写实，要么占位符。
- 低置信度内容禁止晋升（promoted 门槛是多次验证 + 跨场景适用）。
- 门控只约束「写进账本的内容」质量，不阻塞「先记下来」本身——拿不准时可以记，但必须带占位符和低优先级。
