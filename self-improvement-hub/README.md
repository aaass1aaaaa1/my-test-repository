# self-improvement-hub · 自我改进中枢

> Agent 的「记 → 炼 → 用」单一入口：捕获学习、错误与用户纠正，维护可追溯的经验账本，支持晋升项目记忆、提取为技能、每日一项的节奏化改进。

## 解决什么问题

Agent 跨会话工作时有三个断层：**记不住**（踩过的坑下次还踩）、**炼不出**（经验散落在对话里，变不成规则或技能）、**推不动**（改进靠偶发灵感，没有稳定节奏）。本技能把「捕获 → 记录 → 回顾 → 晋升/提取 → 每日推进」压缩成一条确定性工作流。

## 核心能力

| 能力 | 说明 |
|---|---|
| 触发器捕获 | 命令失败、用户纠正、知识缺口、功能需求——信号出现即记录，不用用户开口 |
| 三账本体系 | `.learnings/` 下 LEARNINGS / ERRORS / FEATURE_REQUESTS，条目带 ID、优先级、状态流转 |
| 回顾与晋升 | 定期回顾关账；跨场景适用的经验蒸馏为项目记忆规则，重复模式提取为独立技能 |
| 受控改进 | 默认只记录+提案；晋升/提取必须经用户确认才落盘，长期记忆变更可追溯到具体教训 |
| 每日节奏 | 从改进待办挑 1 项当天可完成的，输出执行步骤+验证方式+记录模板，只给方案不落地 |
| 置信度门控 | 信息不全写 `[需核实:字段]` 占位，严禁编造；低置信度内容禁止晋升 |

## 触发词

自我改进 · 总结经验 · 记一下这个错误 · 又踩坑了 · 以后注意 · 经验沉淀 · 提取为技能 · 每日改进 · 改进待办 · 复盘 · 学习记录

## 快速开始

```
Agent（自动）：命令失败 → 写入 .learnings/ERRORS.md，ID = ERR-YYYYMMDD-XXX
Agent（自动）：用户说「不对，应该…」→ 写入 LEARNINGS.md，类别 correction
用户：「今天改进什么？」→ 读待办 → 挑 1 项 → 输出三件套（步骤/验证/记录模板）→ 等确认
用户：「这个坑踩了三次了，提取成技能」→ 提案 → 确认 → 生成技能 → 原条目标 promoted_to_skill
```

## 工作流（5 步）

1. **判定触发器**——六类信号对照表，先搜后写避免重复条目
2. **记录条目**——按模板写必填字段；敏感信息零容忍；不确定就占位不编造
3. **定期回顾**——统计 pending、关闭已解决项、关联相似条目、升级重复问题
4. **晋升与提取**——三条出路（项目记忆 / 独立技能 / 技术债工单），先提案再落盘
5. **每日节奏**（可选）——一天一项、可完成优先、记录留痕、每周复盘
