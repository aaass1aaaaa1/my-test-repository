# WorkBuddy 技能市场规范速查

面向上架的强制项与建议项全量清单。生成任何技能前先对照此文件。

## 一、目录结构

```
skill-name/                 # 目录名必须与 frontmatter 的 name 完全一致
├── SKILL.md                # 必需，唯一不可省略的文件
├── references/             # 可选：按需加载进上下文的参考文档
│   └── *.md / *.txt
├── scripts/                # 可选：需要确定性执行的脚本
│   └── *.py / *.sh
├── assets/                 # 可选：直接用于产出物的模板与资源
│   └── *.md / *.png / *.svg
└── manifest.yaml           # 上架用清单，非运行时必需
```

分层加载模型决定了资源放哪里：

| 层级 | 内容 | 加载时机 | 成本 |
|---|---|---|---|
| L1 | frontmatter 元数据 | 始终在上下文 | 约 100 token |
| L2 | SKILL.md 正文 | 触发后加载 | 建议 ≤ 5k token / 500 行 |
| L3 | scripts、references、assets | 按需调用 | 无硬上限 |

结论：触发条件必须写进 `description`，写进正文等于没写——正文加载时触发判断已完成。

## 二、Frontmatter 字段

### 必填

| 字段 | 要求 | 常见错误 |
|---|---|---|
| `name` | 小写字母、数字、连字符；3–64 字符；不以 `-` 开头结尾；无连续 `--`；与目录名一致 | 用中文名、下划线、大写字母 |
| `description` | 1–1024 字符；说清"做什么"+"何时用"；含触发词 | 只写功能不写触发场景 |
| `description_zh` | 简短中文介绍，市场详情页展示 | 与 description 语义不一致 |
| `description_en` | 简短英文介绍 | 机翻痕迹重、语义漂移 |
| `version` | 顶层字段，语义化三段纯数字，首版 `1.0.0` | 写成 `v1.0`、嵌套进 metadata |
| `author` | 作者或合作方名称 | 留空或填占位符未替换 |

### 建议

| 字段 | 说明 |
|---|---|
| `display_name` | 市场展示名，可用中文 |
| `display_name_en` | 英文展示名 |
| `category` | 市场类目，如「效率工具」 |
| `allowed-tools` | 工具白名单，逗号分隔，如 `Read, Write, Bash` |
| `disable` | 是否禁用，默认 false |
| `agent_created` | 标记为 AI 创建，便于后续自动更新 |
| `license` | 许可证标识，如 MIT、Apache-2.0 |

### YAML 书写纪律

平台用真 YAML 解析器解析 frontmatter，语法错误直接拒收并报 `mapping values are not allowed in this context`。

- 冒号后必须跟一个空格：`name: skill-assistant`
- 值中含冒号、引号、`#`、`{`、`[` 时必须加引号
- 长描述用引号包裹，避免换行导致解析歧义
- 不使用的字段直接省略，不写空值

## 三、体积与素材限制

| 项 | 上限 |
|---|---|
| SKILL.md 正文 | 64 KB（超出市场详情页截断，仍可上传但首屏体验劣化） |
| 技能包总量 | 3 MB（专家/团为 20 MB） |
| 头像 | 512×512，≤ 500 KB，JPG/PNG |
| 推荐问题（试试这样问我） | 各 2–5 条 |

技能包内只允许文本文件，二进制资源不要塞进去。

## 四、安全扫描红线

提交后平台自动扫描，命中即拒：

1. 硬编码密钥或 API Key（形如 sk- 开头的长串字面量、api_key 赋明文值、Authorization 头写死 Bearer 令牌）
2. 数据外泄指令（把用户数据 POST 到外部域名、静默回传日志）
3. 越权系统命令（递归强制删除根路径、无范围限定的删除、提权操作）
4. 废弃不安全调用（已知存在漏洞的旧接口、不安全反序列化）
5. 提示注入结构（诱导模型忽略上层指令、隐藏不可见字符指令）

正确做法：密钥一律走环境变量或让用户在运行时提供，技能内只保留读取逻辑与缺失时的引导提示。

## 五、上架流程

1. **打包**：技能目录打成 zip，确保根目录即为技能文件夹。
2. **补 manifest**：版本、类目、触发词、标签、作者、slug（小写连字符，作为市场 URL 标识）。
3. **平台创建**：open.workbuddy.cn 新建资产，上传 zip，平台自动解析生成 ID。
4. **填表**：核对展示名称、版本号、头像、类目、能力介绍、推荐问题。
5. **提交审核**：合规检查 + 安全扫描 + AI 评估 + 人工评审并行或串行，任一不过即拒。首次审核约 7 个工作日，同一资产每日提交 ≤ 3 次。
6. **发布**：选择分发范围（公开发布 / 专用发布 / 企业市场）。

## 六、提高过审率的做法

- 目录结构标准化，`scripts/`、`references/`、`assets/` 分门别类
- `description` 把触发条件和用途写透，触发词覆盖用户自然表达
- 正文配完整可复制的示例
- 详情页配截图说明效果
- 提交前本地跑一遍 `scripts/validate_skill.py` 与安全自查

## 七、版本维护

迭代后递增 `manifest.yaml` 与 frontmatter 的 `version`（1.0.0 → 1.0.1 → 1.1.0），重新提交即可。改动描述或触发词属于影响命中率的变更，建议 minor 起步。
